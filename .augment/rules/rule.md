# 任务管理策略

## 何时使用任务管理

- 用户明确要求规划或任务分解
- 复杂多步骤任务 (文件数 > 3)
- 需要跟踪进度的工作
- 需要协调多个相关变更
- 系统级修改和重构

## 任务状态管理

- `[ ]` NOT_STARTED: 未开始的任务
- `[/]` IN_PROGRESS: 正在进行的任务
- `[-]` CANCELLED: 已取消的任务
- `[x]` COMPLETE: 已完成的任务

## 批量更新原则

```json
// 推荐: 批量更新多个任务
{
  "tasks": [
    { "task_id": "prev-task", "state": "COMPLETE" },
    { "task_id": "current-task", "state": "IN_PROGRESS" },
    { "task_id": "next-task", "name": "更新后的任务名称" }
  ]
}
```

# 编辑执行规则

## 必须执行

1. **信息收集优先**: 编辑前必须调用 `codebase-retrieval`
2. **详细上下文**: 获取所有相关符号、类、方法的详细信息
3. **单次调用**: 在一次调用中获取所有需要的信息
4. **保守编辑**: 尊重现有代码库结构和风格
5. **并行信息收集**: 同时获取多个相关组件的信息

## 信息收集模式

```python
# 编辑前必须询问的信息 (支持并行查询)
if 调用方法:
    并行询问("类和方法的详细信息", "相关依赖", "使用示例")
if 使用类实例:
    并行询问("类的完整定义", "继承关系", "接口实现")
if 涉及属性:
    并行询问("类和属性的详细信息", "属性类型", "访问模式")
if 多个相关:
    并行询问("所有相关符号的信息", "依赖关系", "调用链")
```

## 禁止行为

- 不使用 `codebase-retrieval` 直接编辑

- 使用 sed 或命令行工具编辑文件
- 手动编辑包配置文件
- 串行执行可并行的信息收集操作
